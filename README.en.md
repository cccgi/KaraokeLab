# KaraokeMaker

A native macOS karaoke video editor — think CapCut/Final Cut, but purpose-built for turning a song
into a finished karaoke video. Drop in an audio file, get word-synced lyrics (typed by hand or
generated by AI straight from the vocals), style the text, add a background and overlays, color
grade, and export a subtitle file or a finished video with karaoke-style highlight timing baked in.

Everything runs **locally on your Mac** — no cloud processing, no account, no per-export cost. The
only network access the app ever makes is the one-time model download for the optional AI lyrics
feature (see [Auto Karaoke](#auto-karaoke-ai-no-lyrics-needed) below).

- **Swift Package** (no `.xcodeproj`), SwiftUI + AppKit hybrid, macOS 13 (Ventura) or later.
- Universal: builds natively on both Apple Silicon and Intel Macs.
- Offline audio separation (MDX-Net / MDX23C, ONNX Runtime) and forced alignment (MMS, ONNX CTC) —
  no server round-trip for the timing engine.
- Optional local AI transcription (Qwen3-ASR, via a self-contained Python runtime) for songs where
  you don't already have lyrics.

## What it does

| Area | What you can do |
|---|---|
| **Import** | Bring in an audio file (MP3/WAV/etc.), images, and video clips into a project's media pool. |
| **Lyrics & timing** | Paste lyrics and auto-align them to the vocals, *or* let the app listen to the song and write the lyrics for you (AI, offline). Word-level timing, hand-adjustable on the timeline. |
| **Timeline editor** | Multi-track timeline (music, lyrics, karaoke, up to 3 overlay layers) with trim/split/drag/duplicate, snapping, zoom, undo/redo, keyboard shortcuts, and a real-time waveform. |
| **Styling** | Font, size, weight, case, letter spacing, sung/unsung colors, outline, shadow, and layout — save your own presets or use the built-in ones. |
| **Backgrounds & overlays** | Static image or video background (with Ken Burns), up to 3 overlay layers (image/video/text) with drag, resize, rotate, opacity, blend modes, fades, and crossfades. |
| **Color engine** | A real tonal-region color pipeline (exposure, contrast, highlights/shadows/whites/blacks, temperature/tint, vibrance/saturation, tone curves, HSL, LUTs, vignette, histogram/scopes) — applied consistently in preview and export. |
| **Music visualizer** | 7 waveform/spectrum visual styles driven by a live FFT of the track. |
| **Export** | SRT and ASS (karaoke-style `\kf` subtitles), or a rendered video: transparent (ProRes 4444, alpha channel — for compositing over other footage) or opaque (H.264/MP4 or ProRes). Presets from 720p up to 4K, including vertical (9:16) and square (1:1). |
| **Projects** | Everything (audio, lyrics, timing, style, color, project media) saves into one `.kbproj` file you can reopen and keep editing — including on a different Mac. |

### Auto Karaoke (AI, "no lyrics needed")

If you don't have the lyrics typed out, KaraokeMaker can listen to the song itself: it separates
the vocals, transcribes them (Qwen3-ASR, running locally via a bundled Python runtime — nothing
leaves your Mac), flags any words it isn't confident about, and times everything using the exact
same alignment engine as the "I have lyrics" path. You review/fix the transcript before it's
applied to your project.

This is the one feature that needs extra setup on a fresh machine — see below.

## Requirements

- macOS 13 (Ventura) or later
- Xcode 15 or later (or just the Xcode Command Line Tools — this is a Swift Package, not an
  `.xcodeproj`, so the full Xcode app isn't required to build)
- ~600 MB free disk space for the three bundled ONNX models, plus (only if you want the AI
  "no lyrics needed" feature) roughly another 6 GB for the Python/PyTorch runtime and the
  Qwen3-ASR 0.6B + 1.7B model weights

## First-time setup on a vanilla Mac

### 1. Install the Xcode Command Line Tools (if you haven't already)

```bash
xcode-select --install
```

### 2. Get the source

```bash
git clone https://github.com/cccgi/KaraokeLab.git
cd KaraokeLab/KaraokeApp
```

### 3. Restore the ONNX models

The three model files that power vocal separation and forced alignment (~580 MB combined) are
**not** stored in this git repo — they're well over GitHub's 100 MB file limit. `Package.swift`
expects them as real files on disk at `Sources/KaraokeMaker/Resources/`, so they need to be put
there before the first build. A helper script does this for you:

```bash
./Scripts/setup-client-runtime.sh --skip-runtime
```

One of the three models (`UVR-MDX-NET-Voc_FT.onnx`) has a verified public source and downloads
automatically. The other two (`mdx23c-vocinst.onnx`, `mms-aligner-uint8.onnx`) were hand-converted
by the original developer and have no public mirror — if you don't already have a copy of this
project with them in place, point the script at one:

```bash
./Scripts/setup-client-runtime.sh --skip-runtime --models-source "/path/to/5_KaraokeApp_source_with_git.zip"
# or a plain folder containing the three .onnx files:
./Scripts/setup-client-runtime.sh --skip-runtime --models-source "/path/to/folder"
```

Every file is checksum-verified (sha256) before it's accepted, regardless of where it came from.

### 4. (Optional) Set up the AI "no lyrics needed" runtime

Only needed if you want to use Auto Karaoke during development. Skip this if you only care about
the manual "I have lyrics" path, or if you're building a release package (which bundles its own
runtime — see `Scripts/package-release.sh`).

```bash
./Scripts/setup-client-runtime.sh --skip-models
```

This creates a Python virtual environment at the exact path the app's dev build looks for
(`~/qwen3_asr_m4_test/venv_official` on Apple Silicon, `~/qwen3_asr_intel_test/venv_qwenasr` on
Intel), installs the pinned PyTorch/transformers/qwen-asr versions, and pre-downloads the
Qwen3-ASR 0.6B and 1.7B model weights from Hugging Face (a few GB, needs internet once).

Run both steps together with no arguments (`./Scripts/setup-client-runtime.sh`) to do models +
runtime in one go. See `./Scripts/setup-client-runtime.sh --help` for all options.

### 5. Build and run

```bash
./Scripts/pack-local.sh
open dist/KaraokeMaker.app
```

`pack-local.sh` builds a release binary, assembles it into a proper `.app` bundle in `dist/`, and
ad-hoc code-signs it. Re-run this same command after any code change — it's the standard dev loop
for this project. Plain `swift build -c release` also works if you just want to check that the
code compiles, but only `pack-local.sh` produces a runnable, properly-bundled app (icon, resources,
the Auto Karaoke dev-runtime flag, etc.).

First launch may take a few extra seconds while macOS scans the new app bundle — subsequent
launches are fast.

## Usage guide

### The Home screen

The app opens to a project library: a grid of your existing projects (thumbnail, duration, file
size, last-modified) with search, a **Create project** button, **Open another project…** (to open
a `.kbproj` from anywhere on disk), and a Trash. Language (Vietnamese/English) is switchable from
the top-right corner.

### Starting a project

**Create project** → import an audio file. That's the only required input to get going; everything
else (background, overlays, styling) can be added later.

### Getting lyrics: two paths

Once audio is imported, you choose how to get lyrics:

- **I have the lyrics** — paste or type them in, then the app aligns them to the audio
  automatically (word-level timing included).
- **No lyrics needed — Auto Create Karaoke** — the app analyzes the song (vocal separation),
  transcribes it with AI, and shows you the draft with any uncertain words flagged before handing
  it to the same alignment engine as the manual path. You can cancel at any point, or switch to
  the manual path with the transcript pre-filled.

Both paths converge on the same result: a set of lyric lines with word-level start/end times you
can fine-tune by hand afterward.

### The editor

Once a project has audio, it opens into the main editor:

- **Left panel** — tabbed: Create Karaoke (the AI/manual lyrics flow above), Video Background,
  Add Text, Audio Waveform, Media (your imported files).
- **Center** — live preview of the karaoke video, with transport controls (play/pause, skip,
  scrubber, current/total time) and a Karaoke on/off toggle to preview with or without the
  beat-only track.
- **Right panel** — the Inspector: text style controls when a lyric line is selected, or
  clip/overlay properties (position, blend, fades, color) when something on the timeline is
  selected.
- **Bottom** — the Timeline: Music / Lyrics / Karaoke tracks plus up to 3 Overlay lanes, each with
  its own mute/hide/lock toggle.

### Timeline basics

- Click the ruler or empty timeline space to move the playhead.
- Drag a clip body to move it; drag a clip edge to trim it (for overlay clips, the left edge trims
  the source in-point, not just the timeline position).
- ✂️ / ⌘K splits at the playhead. ⌘C/⌘V copies/pastes. Delete removes. Duplicate makes a copy.
- Snapping to adjacent clip edges, the playhead, t=0, and lyric line boundaries (hold ⌘ to
  temporarily disable).
- Zoom with the toolbar buttons, ⌘=/⌘−/⌘0, ⌘+scroll, or pinch. **Fit to window** zooms to show the
  whole song.
- Full undo/redo (⌘Z/⌘⇧Z) for every edit — dragging a clip counts as one undo step, not one per
  frame of the drag.

### Styling the karaoke text

Select a lyric line (or the default style, if none is selected) in the Inspector's **Karaoke Text
Style** panel: font, size, bold/italic/underline, case (UPPER/lower/Title), letter spacing, and
separate colors for sung vs. unsung text. Save your own combination as a reusable preset, or start
from one of the built-in ones.

### Backgrounds, overlays, and the music visualizer

- **Video Background** tab — set a static image or video as the backdrop, with Ken Burns pan/zoom
  for stills.
- **Overlays** — drag files from the Media pool onto an overlay lane on the timeline. Each overlay
  clip supports position/scale/rotation (drag directly on the preview), opacity, blend mode
  (multiply, screen, overlay, etc.), fade in/out, and cross-dissolve into the previous clip.
  Video overlays can optionally carry their own audio (off by default).
- **Music visualizer** — 7 waveform/spectrum styles reacting live to the track, toggle from the
  Add Text/visualizer controls.

### Color grading

The Inspector's color panel applies a proper tonal-region pipeline — Exposure, Contrast,
Highlights, Shadows, Whites, Blacks, Temperature, Tint, Vibrance, Saturation, plus Tone Curves
(draggable per-channel curve), HSL (8 hue bands), `.cube` LUT support, and a vignette — with
histogram/waveform/vectorscope readouts. It applies identically to backgrounds and overlays, in
both preview and the final export, so what you see is what you get.

### Exporting

Click **Export** (top right) and choose:

- **SRT** — plain subtitle file.
- **ASS** — karaoke-style subtitles with per-word highlight timing (`\kf` tags) for players/editors
  that support it (e.g. importing into CapCut).
- **Transparent video** — `.mov`, ProRes 4444 with an alpha channel, for compositing your karaoke
  text/overlays over other footage in another editor.
- **Opaque video** — `.mp4` (H.264) or ProRes `.mov`, a fully rendered final video with your chosen
  background baked in.

Resolution presets range from 720p to 4K, including 9:16 (vertical/Shorts/Reels) and 1:1 (square).
Any trim/fade you've set on the main audio track is respected in the export.

### Saving and project files

**Save** / **Save as** writes a `.kbproj` file (JSON) containing the full project state — audio
reference, lyrics, timing, style, color, media pool, and export settings. Opening a `.kbproj`
restores everything exactly as you left it, including on a different Mac (media is packaged into
the project on save). Undo history does not persist across a save/reopen, but every other project
state does.

## Project layout (for developers)

If you're going to work on the app itself, read `CLAUDE.md` first — it has the house rules
(notably: a short list of alignment/timing files that must not be modified, since they've been
broken by well-intentioned "improvements" before). Then:

- `docs/ARCHITECTURE.md` — how the app is actually put together (state ownership, the playback
  clock, timeline coordinate system, concurrency model).
- `docs/FEATURE_MATRIX.md` — every feature, with a status (functional/verified/broken/etc.).
- `docs/PROGRESS.md` — a running log of what's been done, including root-cause writeups for
  tricky bugs.
- `docs/KNOWN_ISSUES.md` — open bugs and their investigation history.
- `docs/ROADMAP.md` / `docs/COLOR_ENGINE.md` / `docs/COLOR_ENGINE_AUDIT.md` — what's planned and
  the color engine's design in detail.
- `Scripts/` — `pack-local.sh` (dev build/run loop), `package-release.sh` (self-contained release
  build with the AI runtime bundled inside the `.app`), `setup-client-runtime.sh` (this doc's
  setup script), `audit-release.sh`.

## Known limitations

- The AI "no lyrics needed" transcription runs about 75-80% word accuracy on unseen Vietnamese
  songs today (~22-25% word error rate) — it's a solid starting point you review and correct via
  the flagged-uncertain-words UI, not a finished transcript. See `docs/KNOWN_ISSUES.md` for the
  detailed numbers and what's been tried to improve it.
- Not yet code-signed with a Developer ID or notarized — macOS Gatekeeper will warn on a build
  shared between machines until that's done (planned, not started).
- Single main audio track only (no multi-clip music editing) — a deliberate scope decision, not a
  missing feature.
